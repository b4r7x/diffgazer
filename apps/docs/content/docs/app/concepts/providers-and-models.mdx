Diffgazer does not run a model of its own. It is provider-agnostic: you configure one of **thirteen selectable products**, satisfy that product's admission checks, pick an exact admitted model, and Diffgazer talks to it directly from your machine. Switching products or models is a configuration change, not a reinstall. Your credentials and source never pass through a Diffgazer-hosted service. See [Privacy](/app/concepts/privacy) for where credentials and review content actually go.

## Supported products

The provider picker lists thirteen selectable products drawn from the [canonical support matrix](/app/reference/providers#canonical-support-matrix): Google Gemini, Z.AI, OpenRouter, Groq, Cerebras, DeepSeek, Qwen International, Moonshot Open Platform, Mistral, Ollama, Local OpenAI-compatible, OpenAI Codex CLI, and GitHub Copilot CLI.

Each product is a distinct transport contract. Hosted API products require a credential reference and an allowed endpoint or region tuple. Local HTTP products bind to a validated loopback endpoint. Local CLI products use vendor-managed local auth already on your machine. None of them share credentials across products, and Diffgazer does not fall back to another product when one fails.

Removed records such as the old Z.AI Coding Plan may still appear for migration, but they are not selectable. Experimental, deferred, and rejected candidates in the matrix are documentation-only in this tranche. **A compatible endpoint, free credit, or local binary cannot override the frozen verdict** at runtime.

## How models are listed

You do not type model names by hand. Diffgazer discovers exact model IDs through the configured product tuple and rejects aliases, routing selectors, and marketing names.

For catalog-backed hosted products, Diffgazer first uses a non-empty models.dev cache that is less than a day old when available. Otherwise, unless `DIFFGAZER_OFFLINE` is set, it requests the live shared catalog. When a live request is skipped, fails, or does not contain the selected provider, Diffgazer falls back to a non-empty cached list for that provider even if it is stale, then to the bundled offline snapshot. The picker identifies cached and snapshot results, offers Retry, and shows when cached data was fetched.

OpenRouter does not use the shared snapshot. Its picker first reuses a non-empty cache that is less than a day old and belongs to the same API key. When that cache is missing or stale, it requests OpenRouter's live, account-scoped model route; if the refresh fails, it can fall back only to a stale cache for that same key. OpenRouter requires a **pinned downstream route** — routing selectors are rejected.

For every selectable product, the model you select must pass that product's exact-model policy and appear in the admitted discovery result for your configuration. Arbitrary model IDs are rejected at save time.

## Choosing a model

The right model depends on the trade-off you want between speed, cost, and review depth. Several hosted products ship with a suggested starting model, but every choice is explicit and exact. Higher-cost models such as Qwen Coder Plus require live evidence before they can be selected.

For a side-by-side view of every product, transport family, endpoint, structured-output posture, and enablement gate, see the [providers reference](/app/reference/providers).
